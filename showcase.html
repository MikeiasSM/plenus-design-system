Premissa

Como a estilização deve se dar

Arquitetura CSS oficial do sistema: previsível, escalável e de fácil manutenção, pensada para uma aplicação web de grande porte e ciclo de vida longo (LTS). Toda linha de CSS do sistema — e dos produtos que o consomem — se encaixa nesta estratégia.

Estratégia de CSSabordagem híbrida em camadas

A adoção é híbrida e em camadas: cada camada tem responsabilidade exclusiva e só enxerga a camada de cima. Nada de estilos de página no global, nada de valores visuais fora dos tokens.

Design Tokensfonte da verdade dos valores visuais — styles/tokens.css
↓
CSS Global Mínimoreset, normalização e tipografia base — styles/globals.css
↓
Componentesum par Componente.tsx + Componente.module.css por componente
↓
CSS Modulesescopo isolado por componente — sem colisões, sem efeitos implícitos
↓
Páginas / Featurescomposição nos projetos consumidores — nunca no global
Princípio arquitetural: Global define a base. Tokens definem o sistema visual. Componentes definem o comportamento visual local.

globals.css

  • Reset e normalização
  • Configurações de html e body
  • Tipografia base
  • Estilos realmente globais

tokens.css

  • Cores
  • Espaçamentos
  • Tipografia
  • Bordas e raios
  • Sombras
  • Breakpoints e demais valores compartilhados

CSS Modules

  • Estilos específicos de cada componente
  • Isolamento de escopo
  • Evitar colisões entre componentes

Regras

  1. Evitar estilos de componentes no CSS global.
  2. Todo componente reutilizável deve possuir seu próprio CSS Module.
  3. Valores visuais compartilhados devem utilizar tokens.
  4. Evitar duplicação de valores fixos.
  5. Alterações em um componente não devem afetar outros componentes implicitamente.
  6. Estilos globais devem ser exceção, não padrão.
Vantagens e Limitaçõeso que ganhar · o que custar

Vantagens

  • Escopo previsível: cada componente isola seus estilos; uma mudança não vaza para outros implicitamente (regras 1, 2 e 5).
  • Fonte de verdade única: cor, espaço ou raio mudam no token e propagam para todos os produtos e temas.
  • Manutenção LTS barata: refatorações seguras e superfície de regressão reduzida — o global quase nunca muda.
  • Temas e produtos sem esforço: dark theme é troca de tokens; um novo app consome o mesmo pacote visual.
  • Onboarding rápido: estrutura explícita + 6 regras objetivas — qualquer pessoa sabe onde cada estilo vive.
  • Menos CSS: sem valores duplicados, os módulos nascem pequenos e focados.

Limitações e custos

  • Depende de build: CSS Modules exigem bundler (Vite/webpack); em HTML puro o isolamento é simulado — como nesta página.
  • Repetição deliberada: módulos não compartilham seletores; o que se repetiria vira token ou componente, nunca CSS "utilitário".
  • Mais arquivos: um .module.css por componente adiciona cerimônia em coisas muito pequenas.
  • Tokens estáticos em @media: variáveis CSS não funcionam dentro de media queries; breakpoints viram literais documentados ou constantes TS.
  • Exige disciplina: "global como exceção" depende de revisão — o atalho de jogar estilo no globals precisa ser bloqueado.
  • Custo inicial: em projetos pequenos ou descartáveis, a estrutura demora a pagar o investimento.

Nesta documentação — que roda sem build — os "módulos" são simulados pelos blocos pl-* do showcase.css; na migração React cada bloco vira um Componente.module.css com este mesmo conteúdo.
